## 要件と現在の範囲

2026-10-24に、オーナーはブラウザ表示中だけでなく、PCのスリープ・電源オフ中も収集することを要求しました（Issue #61）。
既存の認証付きCloudflare Workerと、アカウント単位の`AccountVault` Durable Objectを使う実装です。
標準のローカル設定では無効です。2026-10-24に承認を受けて専用の本人限定Workerを公開しました。2026-10-27 JSTに本人のGoogleログインが成功し、公開フィード1件を15分間隔で収集する設定を開始しました。
ローカルのアラーム検証と公開された設定準備中画面は、継続稼働する収集サービスの証拠ではありません。課金変更や実プロバイダーキーの入力は行っていません。

「設定 → PCを閉じている間の収集」で、15分・30分・60分間隔のクラウド収集を明示的に開始・更新します。
このブラウザの購読先と既存のクラウド購読先を合わせ、重複を除いて最大50件、URLデータ16 KBまで登録します。
ローカルで購読先を追加した場合は「設定を更新」が必要です。追加した購読先を自動でアップロードしません。
「クラウド収集を停止」しても未取り込み結果は残ります。ログアウトだけでは、設定済みの収集は停止しません。
認証不可、実行環境の未設定、設定の競合、取得失敗、容量不足を表示し、成功した収集として扱いません。
登録済みの各配信元では、クラウドの最終取得成功時刻を、ブラウザ内の最終取得時刻と次回更新予定から分けて表示します。
クラウドで一度も取得に成功していない場合は、そのことを明示します。RSSに変化がなく新しい取得結果が作られない場合も、クラウドの成功時刻は進みます。その後に取得が失敗した場合は、以前の成功時刻を再試行の警告とともに保持します。

クラウド取得先は3ホスト固定から、公開HTTPSの配信元ドメインに対応する方式へ変更しました。認証付きの`/api/feeds/fetch`もRSS検出・記事HTML取得に同じ条件を適用し、アカウントごとに毎分20リクエストまでに制限します。
URL内の認証情報、標準以外のポート、直接指定・別表記のIP、ローカル・予約名、Quilna自身のホスト名は拒否します。リダイレクト先も再検証し、URLのフラグメントは除去します。
Workersは必須の互換フラグ[`global_fetch_strictly_public`](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#global-fetch-strictly-public)を有効にしたglobal `fetch`を使います。
Cloudflareの仕様では、自分のzone宛ても公開インターネット経由になり、既定のorigin保護を迂回し得る経路を使いません。この実装はそのプラットフォームの境界に依存し、独自のDNS固定やVPC・private-origin bindingは使いません。
別実装のローカルNodeエンドポイントは引き続きDNS応答を検証し、公開アドレスへTLS接続を固定します。オフラインWorkersプレビューは外部通信を禁止します。
ログインやスクリプト描画が必要なサイト、サーバーからの取得を拒否するサイト、対応する応答を返さないサイトは理由を示して失敗する場合があります。任意の配信元ドメインへの対応は、すべてのサイトで本文抽出に成功する保証ではありません。
ブラウザのCookieや認証ヘッダーは転送しません。応答は2 MB、期限は12秒、リダイレクトは3回までで、XMLの実体・DOCTYPEを拒否し、検出用HTMLはブラウザ内で実行せず扱います。

## 永続化と受け渡し

Durable Objectに購読スケジュール、最終成功時刻、失敗回数、再試行期限、未取り込みのRSS応答を保存します。
[アラーム](https://developers.cloudflare.com/durable-objects/api/alarms/)がブラウザからの通信なしでObjectを起動します。
Cloudflareのアラームは少なくとも1回の実行を保証するため、通信前に60秒間の取得権を永続化し、設定リビジョンと取得権が一致する結果だけを確定します。
1回のアラームでは期限を迎えた最大2件を取得し、通信前の同じトランザクションで復旧用アラームも保存します。
失敗時は5分・10分・20分・40分・最大60分後に再試行します。停止・設定変更は進行中の応答を無効にします。
応答のハッシュが変わらなければ未取り込み結果を重複追加せず、取得成功に応じて次回時刻を進めます。
定期収集であり、配信元がフィードから記事を削除する前にすべて取得できる保証ではありません。

未取り込み結果は、資格情報・予算とは別のキーに、分割した本文とメタデータを永続ストレージのトランザクションで保存します。
アカウントごとの上限は100応答、UTF-8本文20 MB、メタデータ110 KBで、いずれかの上限に達すると停止します。
容量不足では既存結果を削除せず、スケジュールを停止します。ブラウザからの受け取り確認で容量が空くと再開します。
保存した応答は信頼しないソースデータとして扱い、RSS全体の解析とテキスト抽出はブラウザで行います。
次に表示されたオンラインのブラウザが1回につき最大5応答を取得し、各結果をIndexedDBへ確定した後、受け取り済みIDを通知します。
未取り込み結果があれば15秒後、それ以外は画面表示中の60秒ごとに状態を確認します。
接続失敗・タイムアウト・一時的なHTTPエラー（408・429・5xx）では、初回接続や受け取り確認の失敗も含め、30・60・120・240・以後300秒ごとに状態確認と取り込みを再試行します。1回の処理が成功すると通常の間隔に戻ります。認証・環境設定・アカウント検証・状態データの形式・ローカル保存の異常では自動再試行せず、明示的な復旧を待ちます。設定変更と削除の要求は自動で再送しません。
保存失敗、画面移動、応答消失では、確認されていないサーバー側の結果を再試行用に残します。受け取り確認は重複しても安全です。
不正なXMLや破損した保存結果は未取り込みのまま残し、設定画面に配信元URL・取得時刻・理由を表示します。
正常な結果の取り込みは妨げません。1回に、この画面でまだ失敗していない最大5件を試し、ローカル保存が成功した結果だけを受け取り確認します。
失敗した結果だけが残る場合は、同じ本文を繰り返しダウンロードせず、60秒ごとに状態を確認します。画面の再読み込み、または「取り込めない取得結果を再試行」で再試行します。
状態確認から取得までの間に別のブラウザが削除した結果は読み飛ばし、他の結果の取り込みを続けます。
失敗した結果ごとに「この取得結果を削除」があり、未取り込みのクラウド上のコピーを元に戻せなくなることを確認してから削除します。キャンセルすれば保持します。
この明示的な削除は、認証・CSRFで保護した別のエンドポイントでIDを1件だけ受け付け、受け取り確認と同じ所有者分離・トランザクションによる削除を使います。
削除失敗は理由を表示して再試行可能にし、削除成功で容量不足の停止を解除できます。ブラウザに保存済みの記事や購読設定は変更しません。
通信・アカウント検証・IndexedDBの失敗時は引き続きその回の取り込みを停止し、確認されていない結果を保持します。
収集間隔の選択欄は再表示時にクラウドの保存済み設定を反映し、編集中の選択値をバックグラウンドの状態確認で上書きしません。

取り込み時は既読・保存済みの印、保存済みの固定コピー、取り込んだ原文、翻訳、手動タグを保持します。
古いクラウド応答で、より新しく取得したローカルの配信元・記事本文を置き換えません。
クラウドは受け渡し用の一時保存先であり、完全バックアップや端末間の記事・履歴同期ではありません。1つのブラウザが受け取りを確認すると結果を削除します。
ブラウザ内の記事や印はログアウト後も残り、共用ブラウザプロファイルでのローカルライブラリはアカウント別には分離していません。
クラウドに蓄積するのはRSSに含まれる内容です。リンク先の記事全文の取得、翻訳、読み上げは引き続きブラウザ利用時に行います。

## 有効化と検証

2026-10-24に、オーナーは**新しい本人限定のCloudflare環境**を選択しました。
新規Worker `quilna-private`と新規D1 `quilna-private-auth`の準備には、`wrangler.cloud.example.jsonc`を使います。
独立したデプロイであり、旧`tsumiki-text`の資源やドメイン設定は今回の変更先にしません。
例をignoredの`wrangler.cloud.jsonc`へコピーし、account ID、workers.devのsubdomain、新規D1 ID、許可された本人のGoogleメール1件に置き換えます。
例のIDはplaceholderであり、作成済み資源ではありません。そのままデプロイしないでください。

`compatibility_flags=["global_fetch_strictly_public"]`を維持し、`global_fetch_private_origin`を有効にしないでください。`security:check`と`workers:build`は、追跡対象と存在するignoredの本人用設定について、環境別の上書きを含め、このフラグの欠落・競合を拒否します。
本人限定設定で静的assetがWorkerを迂回する場合やpreview URLが有効な場合も拒否します。公開後は実際のフラグ・asset設定も確認してください。ローカルの検査では、その後のDashboard変更まで確認できません。
Google Web clientのリダイレクトURIは`APP_ORIGIN + /api/auth/callback/google`の完全一致です。
[1Password同期ワークフロー](onepassword-cloud-auth.ja.md)で、承認済みWorkerへ`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`BETTER_AUTH_SECRET`をSecretとして設定します。以後のデプロイでもこれらのbindingを保持してください。
RSS収集にBYOK暗号鍵やLLMプロバイダーキーは不要です。実キー入力と実AI送信は無効のままです。
verified emailの検証と認証migrationは[本人限定の認証設定](owner-only-setup.ja.md)を参照してください。
