# 論文の書誌出典

[English](paper-sources.md) | [日本語](paper-sources.ja.md)

## ブラウザの操作

**設定 → 論文の出典 → 論文を検索・DOIから確認**で `/?view=papers` を開きます。
DOIそのもの、またはHTTPSの `doi.org` / `dx.doi.org` URLを入力し、**DOIをCrossrefへ送って確認**を明示的に押します。
送信前に提供元と送る識別子を表示し、書誌情報を自動保存せずプレビューします。
**この書誌情報を保存**で、このブラウザのプロフィールに取得時点の記録を不変で保存します。
古い記録を開いても、新しい提供元の応答に置き換えません。
対応するDOIは4〜9桁の登録者番号、空白を含まない印字可能ASCIIの接尾辞、全体2,048文字までです。対応外は送信前に拒否します。
URLの認証情報・既定以外のポート・クエリ・フラグメントは拒否します。接尾辞に `?` / `#` がある場合はDOIそのものを入力してください。

保存するのは正規化DOI、題名、登録された著者名/ORCID、種類、版番号、収録先、出版社と登録された主URL、巻/号/ページ/記事番号、公開日、作成/登録更新/索引更新日、登録された関係/更新情報です。
部分的な日付は元の精度を保持し、不足項目は推測せず**不明**と表示します。
取得先と取得日時は確認時点を示します。登録/索引更新日時はメタデータの出来事で、本文改訂の証明ではありません。
関係/更新情報の参照先は取得せず、プレプリントと出版版を統合しません。
更新情報がないことは、訂正・撤回がないことの証明ではありません。
登録された出版社URLは文字列で表示し、DOIリンクは利用者が開いた場合だけ移動します。
提供元の文字列はテキストとして表示し、HTMLとして挿入しません。

**書誌キーワード**は1〜200文字で、改行・制御文字は使えません。
**キーワードをCrossrefへ送って検索**で、提供元がIPと内容を記録する説明を確認したうえで明示的に送信します。
本文ではなく書誌メタデータの検索です。提供元の最初の20件だけを要求し、総該当件数と同じDOIの同一書誌情報の重複数を表示します。
さらに探す場合はキーワードを絞ります。ページ送り・続きの自動取得・検索履歴の保存はありません。
結果は題名・著者・種類・収録先・出版社・公開日を表示し、不足は不明とします。
**このDOIをCrossrefへ送って詳細を確認**で上記のDOI確認を別に行います。一覧の要約をそのまま取得記録として保存できません。
検索中・失敗・中止でも前の成功結果を元のキーワード付きで保持します。入力変更や選択後は、通信が中止を無視しても遅い応答を反映しません。
再読み込みで検索結果とキーワードは消え、保存した記録は保持します。

抄録の保存/表示、PDF/全文の取得、出典抜粋の選択、教材の生成/レビューは接続していません。
[Issue #31](https://github.com/tqer39/quilna/issues/31)のこれらの部分と、[生成の基本導線](https://github.com/tqer39/quilna/issues/7)は未完了です。
書誌情報の取得は、内容の正しさ、査読、本文の版の同一性、出版社のコンテンツの再配布許可を示しません。

## 提供元・利用条件・要求制限

Crossref公開APIの単一レコード `GET https://api.crossref.org/works/{encoded DOI}` と、明示的に送信する一覧 `GET https://api.crossref.org/works` を使います。
一覧は[`query.bibliographic`、`rows=20`、`select`](https://github.com/CrossRef/rest-api-doc)を使い、項目は `DOI,title,author,type,container-title,publisher,published` に限定します。`query.title`・連絡先パラメータ・APIキーはありません。
登録・APIキー・有料契約・メール設定はありません。
資格情報とリファラーを省き、転送を拒否し、DOIまたは上限内の書誌クエリ・選択項目と `Accept: application/json` ヘッダーだけを送ります。
DOIリゾルバー、出版社、別の登録機関、検索APIへ自動で接続しません。
[公式の取得仕様](https://www.crossref.org/documentation/retrieve-metadata/)では、公開要求でもIPと要求内容を記録すると説明しています。
[REST API仕様](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)はほぼすべてのメタデータの再利用を許可する一方、抄録には出版社/著者の著作権が残る場合があると説明しています。
単一レコード応答には抄録が含まれ得て、項目選択前のJSONをメモリで受信します。
書誌の事実情報を選択し、抄録・参考文献・任意の追加項目・記事本文は保存・表示・書き出しから除きます。
ローカル記録の自動期限切れや背景更新はありません。オフラインfixtureで提供元の稼働や実出典の受け入れを確認したとは扱いません。

2026-11-03 JSTに確認した[2026年7月の公式変更](https://community.crossref.org/t/refining-rest-api-limits-for-improved-stability-and-reliability/16137)では、公開枠は単一レコード5要求/秒、一覧1要求/秒です。
両操作はアカウント別ライブラリの切り替え後も共通で最低1秒間隔に制限します。
Web Lockで同一オリジン・同じプロフィールのタブを直列化し、localStorageで次の要求可能時刻を再読込後も保持します。
応答のlimit/intervalヘッダーで間隔を延長し、`Retry-After` があればさらに延長します。429/503では最低60秒待ちます。
自動再試行・ポーリング・一括要求の待ち行列はありません。利用者が可能時刻後に明示的に再試行します。
別のプロフィール・オリジン・同じIPを使う他人との調整ではなく、提供元の制限が優先します。
CORSで任意の制限ヘッダーが公開されない場合は保守的な既定値を使います。クロスオリジン通信が拒否された場合、プロキシや別経路へ切り替えません。
要求は16秒、応答は1,000,000バイトまで。不正UTF-8、DOI不一致、不正な日付、選択配列の上限超過は、部分的な結果を保存せず失敗します。

認証付きWorkerは、ルートの `?view=papers` 文書だけ `connect-src` に `https://api.crossref.org` を許可します。
ほかの記事画面とログイン画面は既存方針を保持します。この変更で認証や配備設定を有効にしません。

## ローカル記録とファイル

独立したIndexedDB `quilna.papers.v1` は最大1,000記録を保存し、一覧は20件ずつ表示します。
選択した事実情報のSHA-256で記録を識別し、同じDOIでも内容が変われば別の記録にします。
同じ内容の保存は最初の取得日時を再利用して上書きしません。同時保存の照合/追加は原子的です。
ダイジェストは競合検知用であり、提供元の署名や本人性の保証ではありません。
容量不足・トランザクション失敗・破損・将来DB版では、追い出しや初期化をせず拒否します。

**この記録をファイルに保存**は選択した記録だけを `QuilnaPaper`、schema version 1として書き出します。
**保存した書誌ファイルを確認**は上限内のUTF-8 JSONを検証し、Crossrefへ通信せず、明示保存前にプレビューします。
未知項目/版、ダイジェスト/取得先の食い違い、不正な事実項目は拒否します。
再書き出しは選んだ記録の事実情報と取得日時を保持し、取り込みで新しい登録情報へ黙って置き換えません。
記事一覧・回答・メモ・アカウント識別子・資格情報を含まず、記事バックアップや[教材ファイル](textbook-sharing.ja.md)とは別です。
既定は同じブラウザのプロフィール内で共通のため、別の人とはプロフィールを分けてください。任意で有効にする[アカウント別ライブラリ](source-document-catalog.ja.md#アカウント別のブラウザライブラリ任意の有効化)は保存した書誌も分離し、書き出しにアカウント識別子は追加しません。Crossrefの要求制限は、そのプロフィールのアカウント間で共通のままです。
クラウド同期、自動削除、記録を管理/削除する画面はありません。

## 検証の範囲

合成fixtureで項目選択、日付精度、登録された版/関係情報、要求上限、一覧の検証/重複除外、クエリの符号化、一覧/DOI共通の制限応答、遅い成功/失敗応答の中止、不変保存と別プロフィールのファイル往復を検証します。
ビルドしたリーダーの実行環境検査では、実ローカル認証とオフラインのGoogle/提供元応答を使い、画面別CSPと明示的なキーワード/DOI送信を確認します。
Crossrefの実稼働/CORS、実出典の利用許可、所有者の操作性の受け入れ、論文から教材を作る経路の完成を示すものではありません。
