# ブラウザでのRSS収集と構成の選択

[English](browser-rss.md) | [日本語](browser-rss.ja.md)

## 起動と確認

`mise exec -- npm run dev`で起動し、<http://127.0.0.1:5173/>を開きます。
ホーム画面は情報収集です。「サイトを追加」にサイト・記事・RSS/AtomのURLを入力し、「フィードを探す」を押します。
スキームのないドメインにはHTTPSを使います。名前付きの候補から「登録して読む」を選びます。見つかっただけでは登録しません。
Zenn・Cloudflare Blogは引き続きワンクリックで試せます。
記事を開いて「この記事を保存」を押し、一覧に戻って「保存した記事」を選びます。
再読み込みして保存内容を確認できます。「サンプル教材」は既存の固定CAA教材を別に開きます。収集した記事からの生成ではありません。

ページが案内するRSS/Atomのalternateリンクを探し、相対URLとHTMLのbase URLにも対応します。
記事ページに案内がなければ、リダイレクト後のサイトのトップページも、同じクライアント側の16秒の制限内で確認します。
候補は重複を除いて最大20件です。入力を変更すると探索を中止し、古い結果を破棄します。
探索用HTMLは不活性なtemplate内で読み取り、スクリプト・画像・埋め込みフレームを画面へ挿入・実行しません。
選んだフィードとすべてのリダイレクト先には、既存の公開HTTPS・DNSの検査を適用します。
フィードの案内がないサイトには、その旨と単独記事の取り込み操作を表示します。名前・話題での検索、任意の巡回、パスの推測、RSSがないサイトからのフィード生成は未実装です。
探索中や失敗時も、取得済みの記事は引き続き閲覧・保存できます。

RSS取得・ページ探索・記事取り込みはローカルのViteプロセス内で、`/api/feeds/fetch`を通して実行します。探索モードの要求でHTML応答を許可します。
本文抽出には共通のブラウザ依存`@mozilla/readability`を使います。クラウドへの公開、ログイン、有料モデルへの接続は追加していません。
`npm run build`は静的ファイルを作るだけで、RSS取得サービスの作成・公開は行いません。
`vite preview`にはこのエンドポイントがありません。任意で有効化する[クラウド収集](cloud-feed-collection.ja.md)は、明示した3つの配信元ホストについて認証付きWorkers取得に対応します。既定では無効です。

## ビューアのデザイン

「設定 → ビューアのデザイン」で、**Studio**（既定・明るいカード表示）、**Editorial**（温かい紙面色・本文の明朝体・1列の記事一覧）、**Focus**（暗い配色・落ち着いた1列の記事一覧）の3種類を選べます。
ナビゲーション・操作・記事データは共通です。選択中の記事や保存・既読の状態を変えず、すぐに切り替わります。
選択はこのブラウザのオリジン内の `quilna.reader.design.v1` に保存します。不明な値はStudioに戻し、保存領域のエラーは表示します。保存に失敗しても現在のページには適用します。
選択欄は名前付きのラジオグループで、キーボード操作と小さなプレビューに対応します。操作部品は高さ44 CSSピクセル以上を保ち、狭い画面では1列に並べ、動きを減らす設定では切替効果を抑えます。
記事本文をタグ編集・翻訳・読み上げの操作より先に表示します。記事内のリンクで、記事を離れず本文や補助操作へフォーカスを移せます。狭い画面には収集メニューを飛ばす「記事へ」も表示します。
配色・文字組み・余白・面のデザイントークンは `src/reader-design.css` にまとめています。現在の適用先はブラウザのRSSビューアで、サンプル教材とネイティブアプリの外観は変更していません。ネイティブへの実装と実機検証は、ブラウザ版を先に完成させる開発順序に従って後から行います。

## RSSの自動収集

購読した配信元は既定で15分ごとに更新します。「設定 → RSSの自動更新」で15分・30分・60分・オフを選べます。設定はこのブラウザのオリジン単位で保存し、ほかの開いているタブにも反映します。
Quilnaの画面が表示され、ブラウザがオンラインと報告している間だけ動きます。画面非表示・オフライン・自動更新オフでは新しい自動取得を始めず、開始済みの取得は従来の16秒のタイムアウト内で完了を待ちます。表示・オンラインへの復帰時に期限を過ぎた配信元を確認します。ページやブラウザを閉じると動かず、動いているとも表示しません。PCのスリープ・電源オフ中の収集は、別途有効化する[クラウド収集](cloud-feed-collection.ja.md)で扱います。ブラウザはクラウドの状態確認を待ってから画面表示中の収集を開始し、初回の重複取得を防ぎます。
15秒ごとのスケジューラ確認で、自身の周期を重複実行せずに期限を過ぎた配信元を更新します。オリジン全体で2つのWeb Lock実行枠と配信元ごとの排他ロックを使い、手動・自動で共有します。自動取得はロック取得後に保存済みの配信元を読み直し、ほかのタブで更新が完了していれば重複取得しません。実行枠が埋まっていれば次の自動確認へ回し、手動操作にはほかの更新が進行中と表示します。
Web Locks非対応のブラウザでは自動収集が利用できないことを明示します。手動更新はそのタブ内で同時2件に制限しますが、この代替経路ではタブをまたぐ保証はありません。

購読済み配信元の取得に失敗しても、記事と最終成功時刻は保持します。失敗回数と再試行時刻をIndexedDBへ保存し、5分・10分・20分・40分・最大60分の間隔で再試行します。再読み込み後も待機を維持し、取得成功時に失敗状態をリセットします。配信元欄にエラーと次回時刻を表示しますが、非表示・オフライン・実行枠待ちで実行が遅れる場合があります。手動の再試行は待機を省略できます。再試行時刻を保存できなければ取得を繰り返さず、自動更新を停止した理由を表示します。保存領域の問題を解決後、設定を選び直して再開します。
更新時は記事の識別子で重複を防ぎ、保存済み記事・既読状態・手動タグを保持します。探索だけで勝手に購読はしません。RSS/Atomが見つからない場合は「この記事を取り込んで保存」で、探索の代替として調べたトップページではなく、最初に入力した記事URLを取り込みます。
[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)と[ページの表示状態](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)を参照してください。有料アダプター・RSS生成・リモートcron・新しい外部サービスは有効化していません。

2026-10-24に、デスクトップ・モバイル表示を合わせたリーダーの94テストが通過しました。このうち自動収集は12ケースです。制御した時計・通信応答で期限、非表示・オフライン待機、再試行待機の永続化、複数タブの同時実行、設定、保存失敗、単独記事への案内を検証しました。実際のアプリ内ブラウザでも公開Zennフィードの取得、次回時刻の表示、間隔変更の再読み込み後の保持を確認しました。実時間で15分間待つ継続運転試験ではありません。単体・サーバーテスト、ビルド、lintは通過し、PR/CIでの統合確認と利用者の操作確認は未完了です。

## 保存するもの

購読、取得した記事本文、既読・保存済みの印は、IndexedDBの`tsumiki.rss.v1`へ保存します。
既存のサンプル教材のlocalStorage履歴とは分離し、保持します。
保存先はブラウザのプロファイルとオリジン単位で、ポートも含みます。別ブラウザ・別ポート・別端末のデータとは共有しません。
サイトデータの消去やブラウザによる削除で失われることがあります。この試作には書き出し・バックアップや端末間同期はありません。
[ブラウザの保存領域の仕様](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)を参照してください。

保存した記事は、後の更新で同じ項目が変わっても、取得時の題名・日付・本文を保持します。
更新で過去の記事・既読・保存済みの印を削除しません。複数タブの変更にはIndexedDBのトランザクションと変更通知を使います。
保存失敗を成功と表示せず、エラーに再試行を用意します。
遅い配信元や取得に失敗した配信元があっても、取得済みの記事は読めます。

フィードの記事を開くと元ページの本文取り込みを一度試み、その間もRSSの情報を読めます。
記事URLを入力して「記事として取り込む」を選ぶと、フィードを購読せずに保存できます。
取り込みに失敗しても保存したリンクやRSS情報を残し、失敗内容と「本文の取得を再試行」を表示します。
リンク情報だけのフィードはその旨を明示し、記事本文として扱いません。
Mozilla Readabilityが不活性なHTMLから本文を抽出します。取り込んだ原文はRSS本文とは別に保存し、フィード更新でも保持します。
取り込んだ`pre`・`code`要素は、文字列とUTF-16の範囲を保持します。コードブロックはインデントと改行を保って横スクロールできる領域に表示し、インラインコードは段落内に表示します。元HTMLは挿入せず文字列から表示要素を作り、保存範囲が不正ならライブラリを削除せずエラーを表示します。
原文と訳文のコードブロックは端末内で構文を色分けします。Studio・Editorialは明るい配色、Focusは暗い配色です。同梱のhighlight.js文法でJavaScript/TypeScript、Python、Bash、JSON、YAML、HTML/XML、CSS、SQL、Go、Rust、Swiftを推定しますが、判定は完全ではありません。インラインコードは単色のままです。元の文字列、選択・コピー、保存した引用位置を保ち、外部通信はしません。判定不能・失敗・10,000 UTF-16単位を超えるブロックは単色で表示し、本文の描画ごとに最大20ブロック・合計20,000単位までを処理します。メモリ内の色分けキャッシュは最大32ブロック・元の文字列64,000単位です。表示だけの変更なので、保存済み原文・訳文の再取り込みや保存形式の移行は不要です。
原文・訳文の各コードブロックに「コピー」ボタンがあり、保存済み記事をオフラインで開いた場合も使えます。インデントと改行を保ってコードだけをコピーし、クリップボードへの書き込み完了後に成功を表示します。非対応や許可されない場合は手動で選択してコピーする案内を表示し、再試行できます。操作ボタンは本文や保存した引用位置に含めません。
以前に取り込んだ記事も読めます。「コードの書式を取り直す」は、元サイトと保存済み本文が旧方式の空白正規化後に一致する場合だけ書式を取得します。本文の変更や取得失敗時は、以前の原文・訳文を保持します。書式の取得に成功すると既読・保存の印と手動タグを残し、古い訳文を解除してコードを保護した再翻訳を可能にします。RSSの本文だけの場合や書式情報のない旧記事では、コードを確実には区別できません。
ログイン必須・スクリプト描画・制限のあるページでは本文を取得できない場合があります。Cookieや認証情報の転送、アクセス制限の回避は行いません。
本文抽出は推定のため一部を省略することがあり、すべてのページの完全な複製を保証するものではありません。
画像・実行可能なマークアップ・埋め込みは表示しません。元記事は選択した場合だけ開きます。
上限は購読50件、1回のフィード応答200記事、RSS本文4万文字、取り込み本文20万文字、翻訳40万文字です。
上限を超える取り込みは失敗を表示し、原文を黙って切り詰めて保存しません。
教材生成とオフラインアプリのインストールは、このリーダー機能の範囲に含みません。ページを閉じた後の収集は[クラウド収集ガイド](cloud-feed-collection.ja.md)を参照してください。

### ハイライトとメモ

記事本文を範囲選択し、**選択範囲をハイライト**から引用を保存できます。選択中は操作ボタンが画面下部に表示されます。**ハイライト・メモ**にはキーボードやタッチでも使える引用文の完全一致検索があり、同じ文が複数ある場合は最初の一致に決めず、引用する箇所を選びます。任意のメモを付け、一覧から本文へ戻り、メモを編集し、確認後に引用を削除できます。インラインコードや段落をまたぐ引用も扱い、元のHTMLやメモは文字列として表示します。

記事DBを変更せず、別のIndexedDB `quilna.highlights.v1` に保存します。記事ID、引用元の題名・URL、原文／訳文、言語、原文・表示本文・表示種別から計算したSHA-256、UTF-16の位置、引用文字列、作成日時、メモ、編集の版番号を保持します。新しい引用には下書き作成時に表示中の題名・URLを使い、保存済み引用の出典は保持します。本文と版が一致するときだけマークを配置します。原文の更新・訳文の置き換え・言語の変更後も、以前の引用とメモは「別の版」として一覧に残し、移動・削除しません。保存するのは引用であり、過去の記事全文のスナップショットではありません。既読・保存・ハイライトは別の状態で、引用したことを理解済みとは扱いません。

上限は引用4,000 UTF-16単位、メモ2,000単位、版をまたいで1記事200件です。件数・編集版の確認と書き込みを同じトランザクションで行い、複数タブによる上限超過や新しいメモの上書きを防ぎます。書き込み中は別の引用への編集切り替えを止めます。失敗時は別タブから更新通知が届いても下書きと失敗表示を保持し、明示的に再試行できます。保存形式の不正や読み込み失敗では記事と保存データを保持し、編集を止め、**ハイライト一覧を再読み込み**で再確認します。別記事や言語表示へ切り替えると未保存の編集下書きは解除されますが、すでに送信した保存は元の記事に対して完了します。遅れて届いた読み込み・保存結果で別の閲覧状態を置き換えません。記事と同様に同じオリジン・ブラウザ内の記録で、サイトデータの消去や退避の制限があり、バックアップ・クラウド同期は未対応です。

[Issue #73](https://github.com/tqer39/quilna/issues/73)の一部です。記事やメモを外部の解析サービスへ送信しません。

### 引用同士のつながり

ハイライト一覧の「この引用をつなぐ」から始めます。「引用のつながり」で同じ記事の別の引用を選ぶか、記事の題名を検索して最大20件の候補から保存済みの引用を選び、理由を入力します。原文・訳文の引用は出典言語・正確な版・位置・文字列・メモを保持します。関連は双方向で、関係図ではどちらの引用からも相手を辿れます。理由の編集と確認後の解除ができ、ハイライトの削除や既読・保存状態の変更はしません。関連付けを学習完了の記録とは扱いません。

別のIndexedDB `quilna.quote-connections.v1` に、関連を保存した時点の両引用、順序に依存しない引用ID、記事ID、理由、作成時刻、編集版を記録します。元のハイライトを編集・削除しても、この引用・メモを上書きしません。記事の関係図には、ハイライト一覧から削除された関連付きの引用も表示し、「この引用のつながりを編集」から管理できます。出典情報を残し、表示中の本文の版・言語・文字列が一致する場合だけ本文の該当位置へ移動します。過去の記事全文を復元する機能ではありません。

理由は2,000 UTF-16単位、関連は各引用・各記事200件までです。両端の件数・編集版の照合と書き込みを同じトランザクションで行います。競合や書き込み失敗時は下書きを保持して再試行でき、編集を取り消して開き直すと新しい版を使えます。読み取り不能や未来の保存形式は、データを削除せず拒否します。パネルを閉じるか引用を切り替えると待機中の読み取りを無効化します。記事を変えると未保存の関連下書きを解除しますが、送信済みの保存は元の引用に紐付きます。記録はこのブラウザ内のみで、クラウド同期・バックアップはありません。

### 学ぶきっかけ

ハイライトの下に、初期状態では閉じた任意の**学ぶきっかけ**パネルを置きます。開いたときだけ表示中の原文または訳文を調べ、記事ライブラリ全体は走査しません。定義・理由・比較・具体例を示す日本語と英語の固定表現から、種類の異なる問いを本文順に最大3件選びます。カードには根拠となる文（24〜600 UTF-16単位）をそのまま引用し、考えるための定型の問いを示します。AIによる要約・重要度・正確性・理解度の判定ではありません。コード範囲、URL、コードフェンスを含む文は除きますが、明示されていないコードは確実には識別できません。一致表現がない本文では候補なしと表示します。他言語を推測せず、対象言語の訳文があれば候補を見つけられる場合があります。

**根拠の本文へ**で正確な引用箇所を選択してフォーカスを移します。ハイライト保存領域が使えない場合も本文へ戻れ、パネルから元の出典も開けます。**引用と問いを残す**は引用と問いを編集可能なハイライト下書きへ入れ、自動保存・既存下書きの上書き・学習完了の記録はしません。保存には既存のハイライトの出典・版・失敗時の保護を使います。保存領域の失敗を明示し、閲覧は続けられます。

問いは個別に非表示・復元できます。非表示は現在の記事・本文・言語の間だけ有効で、記事や表示版の変更、再読み込みで解除されます。パネルを閉じると処理中の探索を中止し、遅い結果で新しい閲覧状態を置き換えません。200文ごとに画面操作へ制御を返します。問いと引用は文字列として表示し、外部の解析サービスへ本文を送信しません。

### 関連記事と情報のつながり

ハイライトの後に、初期状態では閉じた任意の**情報のつながり**パネルを置きます。有効なタグが共通する既読・保存記事を最大3件提案し、共通タグを理由として表示します。タグの手動訂正を優先します。話題の候補であり、記事の内容が一致・支持・反証する根拠とは扱いません。候補の探索はパネルを開いたときだけ開始し、処理を分割して画面操作へ制御を返します。閉じる・記事移動で中止し、ライブラリ検索の処理とは分けます。

候補を選ぶか、ライブラリの題名検索（最大20件）から記事を選び、理由を記入して関連を保存します。**自分で保存したつながり**は自動候補と別に表示します。関連はどちらの記事からも表示でき、理由の編集、相手の記事や保存した外部の出典への移動ができます。候補を非表示にすると、その2記事の組み合わせを双方向で除外します。再読み込み後も保持し、**非表示にした候補を管理**から解除できます。関連の解除では確認を求め、記事とハイライトを保持します。解除した組み合わせは再び候補になる場合があります。記事がライブラリからなくなっても出典の記録を保持し、ローカルの記事移動を無効にします。

### 情報の関係図

**情報の関係図**は、必要なときだけ開く周辺の関係を表示するパネルです。記事は利用者が保存した理由、引用は保存した出典記事と利用者が保存した引用間の関連、話題タグは現在の手動・自動タグに基づいてつながります。実線は保存した記事間・引用間の関連、点線は引用の出典、破線は話題の手がかりで、事実の一致・支持・反証を意味しません。非表示にした組み合わせは保存した関連として描画しません。話題を起点にすると同じタグの既読・保存記事を表示し、記事間の関係を推定・保存しません。

線かカードを選ぶと、理由、該当する場合は正確な引用・メモ、保存した出典リンクを確認できます。**ここを起点に周辺を見る**で記事・引用・話題を新しい起点にし、**前の起点へ**で直近20件まで戻れます。周辺は1ページ8件で、前後のページへ移動できます。ライブラリ全体の網羅的な図ではありません。同じ情報をネイティブのボタンによる一覧とキーボードでも辿れます。3種類のデザインに対応し、狭い画面でも任意の補助表示として使えます。

図を開くだけでは既読・関連の保存・理解済みを記録しません。記事を読む操作を選んだ場合だけ、通常のリーダーの動作になります。**表示中の本文の引用へ**では原文・表示本文のハッシュ、言語、原文／訳文、引用範囲の完全一致を確認してから本文を選択します。別記事の引用は先に出典記事を開き、異なる版・言語は位置を移さず明示します。ライブラリから消えた記事も保存した参照と外部出典リンクを保持します。起点にした引用が削除された場合は、その状態を表示し、関連を保存した時点の引用は探索・管理できるように残します。

取得には既存の記事別インデックスを使い、タグは500記事ごとに処理を譲る中断可能な探索で、1ページと次ページ有無の確認分だけ保持します。閉じたパネルは周辺を読み込みません。閉じる・移動・新しい取得によって古い結果が現在の図を置き換えないようにします。関連・引用の変更通知とライブラリの更新で開いた図を更新します。一部の種類を表示できても、取得に失敗した種類は明示し、再試行で記録を書き換えません。引用間の関連は前述の専用保存領域を使い、クラウド同期・外部解析への送信は追加しません。明示的な学習記録は未対応で、関係図の使いやすさ・物理タッチ端末の受け入れは自動検証と区別します。

### 翻訳と読み上げ

取り込み時に判別したコードは翻訳へ送らず、インラインの識別子も含めて原文のまま訳文へ表示します。インラインコードの前後の文章は分けて翻訳するため、不自然な訳になる場合があります。配信元が`pre`・`code`で示していないコードらしい文章は、推測して保護しません。

「表示中の本文を読み上げ」で、表示中の原文または訳文を、その言語に合う端末内音声で読み上げます。

## バックエンドが必要な範囲

| インターフェース・要件 | 取得と保存の構成 | クラウドのバックエンドは必要か |
| --- | --- | --- |
| 今回のPCブラウザ | ローカルのNode/ViteでRSS取得、ブラウザのIndexedDBへ保存 | 不要です。ローカルプロセスの起動が必要で、RSS更新時はインターネットを使います。 |
| PC・スマホのブラウザで履歴は別々 | 静的なWeb画面と、各端末から届くRSS取得API。履歴は各ブラウザへ保存 | 任意の配信元を扱うには通常、到達可能な取得サービスが必要です。自宅運用やサーバーレスでも構成できます。 |
| PC・スマホで購読・保存記事・履歴を共通化 | 取得に加え、認証付きの同期と永続的な共有保存先 | 共通サービスかプラットフォームの同期機能が必要です。専用サーバーの契約が必須という意味ではありません。今回は未実装です。 |
| 将来のPC・スマホのネイティブアプリを単独利用 | OSの通信機能と端末内DBで直接取得・保存が可能 | クラウドのバックエンドは必須ではありません。共有状態や背景処理は別の設計事項です。 |

ブラウザのJavaScriptは、配信元がCORSで許可しない限り、任意のRSS応答を読めません。
許可された配信元の直接取得や、フィードファイルの取込ならローカルでも可能ですが、一般のURL購読全体はカバーできません。
[CORSの仕様](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)を参照してください。
共通部分はRSS取得APIと任意の同期APIとし、利用画面を後から選べる構成を想定しています。

ローカルNodeの取得APIは、ループバックの`127.0.0.1`への同一オリジンの要求だけを受け付けます。スマホからLAN経由では利用できません。
モバイル幅のテストは画面配置の検証であり、実機スマホや公開済みの共通サービスへの接続確認ではありません。
公開する場合は、認証、利用者ごとの制限、公開環境に合う接続先制限と永続化設計が必要です。
今回はCloudflare/AWSのサービスや、LAN・インターネット向けの待受けを有効にしていません。

## 取得処理の境界

標準ポートの公開HTTPSだけを受け付け、URL内の認証情報とIPアドレスの直接指定は拒否します。
ローカルNodeエンドポイントではDNS応答がすべて公開アドレスであることを確認し、そのアドレスへ接続を固定します。証明書は元のホスト名で検証します。
認証付きのCloudflareエンドポイントは、代わりにプラットフォームの公開経由限定のglobal fetchを使います。[クラウド取得の境界とデプロイ条件](cloud-feed-collection.ja.md)を参照してください。
リダイレクト先も再確認し、追跡は3回までです。全体の待ち時間は12秒、応答は2 MBまでに制限します。
RSS/AtomのXMLではDOCTYPE・実体宣言を拒否します。探索用HTMLの通常のdoctypeは許可し、内容は不活性な状態で扱います。
ローカルAPIの同時実行数と要求サイズを制限し、Cookie・認証ヘッダーや任意のプロキシ設定を転送しません。
これらの対策だけで、この開発用APIをそのまま公開できるという意味ではありません。
