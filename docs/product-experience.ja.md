# サクッと知る・じっくり読む

[English](product-experience.md) | [日本語](product-experience.ja.md)

## 誰のために、何を実現するか

2026-11-18の所有者の要件により、Quilnaは時間がない人が短時間の情報インプットと、時間を取った深い理解を両立する場所とします。
[Issue #205](https://github.com/tqer39/quilna/issues/205)と、[#41](https://github.com/tqer39/quilna/issues/41)のブラウザ受け入れで扱う現在の方針です。
この目的に合うなら既存画面・資材の再設計や再作成も行います。保存済みの個人データと出典は保持しますが、既存実装を残すこと自体を製品要件にはしません。

当面の教科書作成は管理者だけに限定します。個人配備では所有者本人が管理者で、OSS版では環境を運用する利用者自身が管理者です。読者は用意された教科書を使います。利用者自身による作成はWebサービス化する際の選択肢とし、今は有効にしません。

## 今の話題から言葉を探す

「辞書 → 話題の言葉を探す」を開き、情報源を選びます。各情報源の掲載順で最大20件を表示します。異なる情報源の数字や掲載位置を合算して、単一の人気順位にはしません。
Google Trendsは日本の検索キーワードを扱い、同じRSSリンクを持つ別のキーワードもまとめません。共通のRSSリンクを持つ語句からは、日本を対象としたその語句の検索動向を開けます。配信元が関連記事を挙げている場合は、最大3件の見出しを展開でき、各記事のリンクと配信元名を確認できます。Hacker Newsは配信見出し、GitHubは日次のリポジトリを扱います。語句のボタンは各項目に実際に含まれる文字列であり、定義・意味上の関連・生成要約ではありません。
語句を選ぶと辞書を開きます。辞書内では、直前に調べた語句や収録語一覧に戻れます。この履歴は辞書を閉じると消えます。見出しの候補は最大6件で、収録済みの複合語を個々の単語より先に表示します。たとえば「retrieval-augmented generation」を選ぶと、RAGの日本語の意味、出典、関連語を確認できます。Google Trendsでは検索語句全体（最大80文字）を先頭に残します。未収録語では「Wikidataへ送って調べる」を押すと、その語句をWikidataに送り、上位3件のうち日本語の説明がある項目を表示します。各項目から出典を開けます。検索結果は辞書に登録しません。
「保存した教科書を探す」は、このブラウザの教材のテーマ名・題名・節の見出しを検索します。一致した節のリンクを選ぶと、その見出しから読み始められます。収録語は辞書の別名でも照合します。一致した教材は版を示して別タブで開くので、読んでいた記事と辞書をそのまま残せます。OSS版で該当する教材がないときは「この言葉で教科書を作る」から、その語をテーマに入力した作成画面を開けます。出典と抜粋は自分で選びます。

各観測には取得日時と情報源の対象範囲を表示します。配信元の日時は別に保ち、記載のない日時やRSSの集計期間を推測しません。アカウント別のブラウザDB `quilna.trends.v1`に情報源ごとの現在の観測を1件ずつ保存し、15分以内の観測を再利用します。欄を開くとキャッシュを確認し、古い場合は非同期で更新します。「話題を更新」では明示的に再取得できます。辞書を閉じると未完了の通信を中止しますが、開始済みのキャッシュ保存は確定する場合があります。キャッシュの確認・更新操作の開始から16秒を過ぎても保存の確認が届かない場合は、書き込み失敗ではなく確認待ちと表示します。遅れて保存を確認できた場合は、移動や新しい操作によって置き換えられていなければ現在の表示を更新します。話題を調べるだけで購読・既読・保存・自動収集予定を変更しません。

「読書中に15分ごとに更新する情報源」を選ぶと、オンラインで読書画面を表示している間、辞書を閉じても更新します。初期設定はオフで、選択は現在のライブラリに保存します。手動と自動の取得はタブ間で情報源ごとに調整します。新しい保存分を再利用し、自動取得に失敗しても同じ情報源への次の自動送信まで15分以上空けます。読書画面を隠すか離れると、タイマーと通信を停止します。Web Locksを使えないブラウザでは手動更新を利用できます。
更新失敗時は前回の観測を保持します。情報源の変更後に届いた古い結果は表示へ反映せず、別タブが保存した新しい観測を古い観測で上書きしないようトランザクションで確認します。未対応・破損した保存データを黙って置換しません。保存に失敗した取得結果は、今回は表示のみであることを明示して表示できます。再取得できるキャッシュなので、読書ライブラリのバックアップや共有サーバーカタログには含めません。

2026-11-18、ローカルのブラウザから実際のループバック取得サーバーを通して、Google Trends 10件・Hacker News 20見出し・GitHub 15リポジトリを取得し、再読み込み後の保持を確認しました。日付付きのローカル検証であり、本番公開や継続収集の検証ではありません。GitHubの抽出は公開ページの構造に依存します。空の結果や構造の変更ではエラーを明示し、前回の情報を残します。
[Googleの公式案内](https://support.google.com/trends/answer/3076011?hl=en)にRSS書き出しが記載されています。[Redditの2026-11-10公式Changelog](https://support.reddithelp.com/hc/en-us/articles/55472297340308-Changelog-November-10-2026)では2026-11-13のRSS提供終了が案内されており、ローカルの確認でもHTTP 404でした。Redditを接続済みと表示せず、代替APIの接続や有料サービスの有効化も行っていません。

## デザインの進め方

`frontend-design`で読書体験を設計し、[Astryxのデザイン規約](https://github.com/meta/astryx/wiki/Design-Conventions)で情報の強弱、余白、用途別トークン、操作状態とアクセシビリティを確認します。
設計原則を参考にするもので、AstryxのReact実行環境やコンポーネント規約全体を導入するものではありません。

- Studioの配色: 画面背景`#f4f6f3`、面`#ffffff`、主な文字`#182d29`、補足`#52645d`、操作`#21685b`、境界`#d5ddd7`。Editorial・Focusも別の読書表現として残しますが、将来の再設計を妨げる条件にはしません。
- 文字組み: 移動や一覧はシステムのゴシック体、記事は読書テーマに合わせます。題名・本文・補足を区別します。日本語の行長と行間は実際の本文で調整し、欧文の数値をそのまま当てはめません。
- 余白: 8/12/16/24/32pxの役割を定め、情報の関係で使い分けます。新しい操作欄では角丸を共通化し、44px以上の操作領域を設けます。
- 状態: 保存状態を文字と`aria-pressed`で示し、書き込み中を保存成功と見せません。利用できない音声と未収録語を明示します。フォーカスを表示し、辞書から同じ読書文脈へ戻します。
- 動き: 利用者の操作で必要な欄を開きます。装飾の自動再生や新たなアニメーションは追加しません。

```text
Quilna     記事一覧 / 保存 / 取り込み     辞書 / 教科書 / 設定
配信元     一覧の題名と短い案内
           見出しの音声（任意）
           検索と興味・タグでの絞り込み
           題名 / 出典と状態 / 概要 / タグ / あとで読む

記事       本文と出典
           辞書: 短い意味 → 関連語 → 読書に戻る
           教科書: 独立した保存済みの版 → じっくり学ぶ
```

最初の構成は紹介用のランディングページより、実際に読む操作を優先します。
一覧ではタグを短い表示にまとめ、開いたときに配信元のタグ・自動判定・自分のタグを分けて確認できます。
PCと320px幅、長い日本語の題名、キーボード、フォーカス、文字と背景のコントラスト、読書への復帰を画像と動作テストで確認します。
自動検査の成功だけで、所有者の使いやすさの受け入れ、実音声の品質、トレンド実収集、公開キャッシュ配送、LLMの実生成を達成したとは扱いません。
